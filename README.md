# Aurora — защищённый мессенджер

**Готовое приложение для Windows.** Отдельное окно, свой сервер, своя база. Ни браузера, ни интернет-регистраций, ни настройки — запустил и пишешь.

Сквозное шифрование: сервер не может прочитать ни одного сообщения и не знает ни одного имени файла.

---

## Запуск

### Готовое приложение

| Файл | Что это |
|---|---|
| `release\Aurora-Portable.exe` | Один файл. Двойной щелчок — работает, ничего не устанавливается |
| `release\Aurora-Setup-1.0.0.exe` | Установщик. Создаёт ярлык в меню «Пуск» |
| `release\win-unpacked\Aurora.exe` | Распакованная версия, работает сразу |

Ни Node.js, ни браузера, ни интернета — ничего из этого не требуется. Программа сама поднимает внутри себя сервер, базу и хранилище файлов.

### Из исходников

Дважды щёлкните **`start.bat`**. Скрипт сам:
1. проверит Node.js и объяснит, что делать, если его нет;
2. запустит готовое приложение, если оно собрано;
3. иначе установит зависимости, соберёт интерфейс и откроет окно.

Чтобы собрать `.exe` самому: `npm run dist`.

### Что дальше

Зарегистрируйтесь — и всё. Чтобы проверить переписку, запустите программу второй раз: откроется **второе окно** (программа не мешает запускать себя дважды). Зарегистрируйте там второго пользователя и напишите себе.

> Дополнительное окно удобно и на одном компьютере: так можно проверить переписку и звонок, не беря второй телефон.

## Где данные

- **Портативная версия** — папка `data\` рядом с программой.
- **Установленная версия** — `%APPDATA%\Aurora\data`.

Там база переписки и зашифрованные файлы. Скопировали папку — перенесли переписку. Удалили — история исчезла.

## Как это защищено

**Сервер не может прочитать ни одного сообщения и не знает ни одного имени файла.**

### Ключи

- **Ключ личности** — пара ECDH P-256, создаётся в браузерном движке приложения.
- **Резервная копия** — приватный ключ шифруется ключом из пароля (PBKDF2, 600 000 итераций) и в таком виде лежит в базе. Пароль на сервер не отправляется.
- **Ключ устройства** — неизвлекаемый AES-256 ключ в хранилище профиля. Им обёрнут приватный ключ, поэтому дальше пароль не нужен. Скопировать этот ключ нельзя.
- **Ключ чата** — случайный AES-256. Каждому участнику выдаётся завёрнутым на секрет ECDH между ним и создателем чата.

### Сообщения и файлы

Каждое сообщение шифруется AES-256-GCM со своим IV. Дополнительные данные (AAD) привязывают шифротекст к чату и отправителю: переставить сообщение в другой чат или подменить отправителя не получится.

Файлы шифруются блоками по 1 МиБ, имена файлов — отдельно.

### Что видит сервер

Кто с кем переписывается, когда и какого размера сообщения. Содержимое — нет. Это проверяется тестом: `bench/server.mjs` сканирует файлы базы и убеждается, что текста сообщений и паролей там нет.

### Проверка ключа

В настройках показан отпечаток вашего открытого ключа. Продиктуйте его собеседнику и сверьте голосом — так вы убедитесь, что посредника в канале нет.

### Пароль нельзя восстановить

Из него выводится ключ, которым зашифрован приватный ключ. Забыли пароль — потеряли историю. Это следствие сквозного шифрования, а не недоработка.

## Звонки

Медиа идёт **напрямую между участниками** — сервер в разговоре не участвует. Шифрование потока — DTLS-SRTP, встроено в WebRTC.

**В одной сети звонки работают сразу.** Между мобильным интернетом и домашним Wi-Fi нужен TURN-сервер: провайдер применяет симметричный NAT, и без ретранслятора соединение не устанавливается. TURN передаёт уже зашифрованный поток, содержимое ему недоступно.

Настраивается в самом приложении: настройки → раздел «Звонки». Варианты: платный сервис, бесплатный лимит Cloudflare или coturn на недорогом сервере.

## Архитектура

```
electron/         оболочка приложения: окно + запуск сервера внутри
  main.mjs

server/           сервер на Node.js без единой зависимости
  index.mjs       HTTP: API, раздача интерфейса, приём файлов
  db.mjs          SQLite из состава Node.js
  auth.mjs        сессии, scrypt-хеши паролей
  realtime.mjs    поток событий (Server-Sent Events)

src/
  lib/
    crypto.ts      ECDH, AES-GCM, ключи чатов, шифрование файлов
    engine.ts      логика мессенджера
    api.ts         единственный слой, знающий адрес сервера
    vault.ts       хранилище: ключ устройства, кэш ключей чата
    rtc.ts         звонки: WebRTC, медиапоток, демонстрация экрана
    rtc-signal.ts  логика сигнализации — чистые функции, покрыты тестами
    groups.ts      группы
    notify.ts      звук, уведомления, заголовок окна
  hooks/           виртуализация, чаты, профиль экрана
  components/      экраны

bench/             шесть стендов проверки
start.bat          лаунчер для Windows
start.ps1          тот же лаунчер с русским интерфейсом
```

Один и тот же код сервера работает и внутри программы, и отдельно — расхождение двух реализаций было бы источником ошибок.

`start.bat` содержит только ASCII: `cmd.exe` читает `.bat` в системной кодировке, и кириллица внутри пакетного файла превращается в мусорные команды. Весь русский текст живёт в `start.ps1`.
